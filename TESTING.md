## 1. Tooling Evaluation: Why Playwright + Vite SSR Is Optimal

Testing an interactive HTML5 2D Canvas color-by-number game with Web Workers, binary RLE codecs, and mobile touch gestures presents requirements that DOM-only runners (`Jest + JSDOM`) or iframe-bound runners (`Cypress`) cannot cover cleanly:

### Cross-Tooling Capability Summary
- **Playwright + Vite SSR (Selected for Capy)**:
  - *Multi-Touch & Pointer Gestures*: Native `hasTouch`, `pointerId`, and microsecond-timed `pointerdown` / `pointermove` / `pointerup` streams for pinch-to-zoom, one-finger double-tap drag zoom, and inertial pan gliding.
  - *2D Canvas & Hit-Testing*: Direct browser context evaluation (`getImageData`, pixel sampling, `ResizeObserver` viewport checks).
  - *Web Worker & Service Worker Lifecycle*: Real `puzzle.worker.ts` thread execution/cancellation and offline version+scope-isolated (`capy-cache-v<version>:<scopePath>`) Service Worker reload verification.
  - *Engine & Codec Unit Speed*: Loads TypeScript modules directly in Node via `vite.ssrLoadModule(...)` before launching headless Chromium in the same process.
- **Puppeteer**: Supports raw CDP touch dispatch and canvas evaluation, but lacks built-in mobile viewport/safe-area ergonomics and Playwright's auto-waiting locators.
- **Cypress**: Runs inside an in-browser iframe with limited multi-touch fidelity and weaker Web Worker / Service Worker isolation.
- **Jest / Testing Library (`JSDOM`)**: Fast for pure JS functions, but has no real HTML5 2D Canvas rasterizer, `ResizeObserver`, `BroadcastChannel`, or Web Worker execution.

### Key Architectural Advantages
1. **Thin Unified Orchestrator ([`web/scripts/test.mjs`](./web/scripts/test.mjs)) + Modular Suites (`web/scripts/tests/{unit,e2e}/`) + Sub-2s Sanity Gate ([`web/scripts/sanity.mjs`](./web/scripts/sanity.mjs))**:
   - `npm run test:sanity` verifies SemVer/`versionCode` parity, `CHANGELOG.md` SemVer/date ordering, clickable PR links, channel-marker invariants, root `.md` guide indexing, and `.md` formatting/links across the entire repo in `< 2s` with zero browser startup.
   - `npm test` invokes the thin [`web/scripts/test.mjs`](./web/scripts/test.mjs) orchestrator, which delegates Part 1 to modular Vite SSR unit suites under `web/scripts/tests/unit/` (plus standalone domain test modules) and Part 2 to 6 sequential Chromium E2E modules under `web/scripts/tests/e2e/` (`runner.mjs` + `helpers.mjs`), binding an ephemeral preview port automatically when `CAPY_TEST_URL` is unset so concurrent runs never collide on `:3000`.
2. **Deterministic Pre-Baked + Live Worker & Event-Driven E2E Coverage**:
   - Verifies both instant zero-worker startup via `./assets/sample_saves.capy` and live `puzzle.worker.ts` custom photo segmentation, IndexedDB (`capy_game_storage_v8`) persistence, and 100% offline PWA reload.
   - Replaces arbitrary UI-transition, modal, long-press, Co-op, resize, keyboard-shortcut, and breadcrumb sleeps across `web/scripts/tests/e2e/` with deterministic locator visibility, DOM attribute, canvas backing-dimension, `waitForAnimationFrames`, `getStableBoundingBox`, `waitForCondition`, IndexedDB eviction, and URL-hash waits, reserving annotated `INTENTIONAL_TIMING_WINDOW` `waitForTimeout(...)` calls strictly for real debounce (`350ms`), animation, timer-starvation, and negative-absence guards.

## 3. Automated Gesture & Canvas Feature Testing Patterns

When extending `web/scripts/tests/e2e/` (invoked via [`web/scripts/test.mjs`](./web/scripts/test.mjs)) for [`PuzzleCanvas.tsx`](./web/src/components/PuzzleCanvas.tsx), follow these deterministic patterns:

### 1. Google Maps-Style One-Finger Double-Tap-and-Drag Zoom
1. Dispatch `pointerdown` at $(x, y)$, wait 30ms, and dispatch `pointerup` (first tap).
2. Within 200ms (below `DOUBLE_TAP_TIMEOUT = 350ms`), dispatch second `pointerdown` at $(x, y)$.
3. Dispatch `pointermove` downward $(x, y + \Delta y)$ to zoom **in** (or upward to zoom **out** when `reverseDoubleTapZoom` is `false`), then `pointerup`.

### 2. Smooth Pan Momentum (Inertial Gliding) & Touch Cancellation
1. Dispatch `pointerdown` at $(x_0, y_0)$.
2. Dispatch rapid `pointermove` steps over ~80ms so flick velocity exceeds $0.18\text{ px/ms}$, then `pointerup`.
3. Dispatch an immediate `pointerdown` mid-glide to verify zero-latency momentum cancellation.

### 3. Corner Panning Bounds (`clampCanvasOffset`)
1. Zoom to $2.5\times$ and pan toward the top-left corner $(0, 0)$.
2. Assert the artwork corner can pan comfortably past the viewport center:
   $$\text{panOffset.x} \le \frac{\text{containerWidth}}{2}$$

## 4. Continuous Integration Pipeline ([`deploy-branch.yml`](./.github/workflows/deploy-branch.yml), [`release.yml`](./.github/workflows/release.yml) & [`deploy-cloudflare.yml`](./.github/workflows/deploy-cloudflare.yml))

Capy uses a 3-tier `Alpha -> Beta -> Production` GitHub Actions architecture paired with Cloudflare Workers edge deployment:

0. **Target Job (`prepare`, `deploy-branch.yml`, `contents: read`, `pull-requests: read`)**:
   - Resolves `target_dir` (`/alpha/<number>/`, `/beta/`, or `/`), `checkout_ref`, `is_docs_only`, `is_main_sync`, `is_draft`, `has_web_changes`, and `skip` flags once before downstream jobs run.
1. **Build & Test Job (`deploy-branch.yml`, `contents: read`, required)**:
   - Runs a `< 2s` pure-Node `npm run test:sanity` check on pure `.md`/metadata PRs (`is_docs_only`, zero `npm ci`) or verified `origin/main`-identical `sync/beta-from-main -> beta` ancestry sync PRs (`is_main_sync`) against the resolved PR merge ref (`checkout_ref`) before skipping Web/Android compilation and Pages deploy.
   - Otherwise restores cached `web/node_modules` (`actions/cache@v6` keyed on `web/package-lock.json`, running `npm ci` only on miss), runs `npm run test:sanity` (`< 2s`), `npm run lint`, `npm run build`, and headless `node scripts/test.mjs --unit` (zero Chromium), and uploads `web-dist` (`web/dist/`) for downstream async jobs.
   - Runs in parallel across PR branches (`feature/* -> beta`, `dependabot/* -> beta`, and `beta -> main`) with `inputs.target_branch` concurrency isolation; `dependabot/* -> beta` PRs run `Build & Test`, `Android APK`, and `Playwright E2E` (when web files change) while skipping Pages deploys.
2. **Android APK Job (`deploy-branch.yml`, `contents: read`, async)**:
   - Runs asynchronously after `Build & Test` (downloading `web-dist` without blocking `Build & Test` or auto-merge), sets up JDK 17 + Gradle, executes `./gradlew app:testDebugUnitTest app:lintVitalRelease app:assembleDebug --build-cache`, and stages/uploads `build-artifacts` (`staging/web/` + `staging/apk/capy.apk`) for Pages deployment.
3. **Playwright E2E Job (`deploy-branch.yml`, `contents: read`, smart tiered async on `beta`/Alpha, required for `main`)**:
   - Runs after `Build & Test` on ready-for-review (`draft == false`) non-docs/non-main-sync PRs targeting `main` (always) or `beta` (only when `has_web_changes == 'true'`), on `push` to `main` (only when `has_web_changes == 'true'`), and on `workflow_dispatch` targeting `main` (or when `run_e2e == true`), skipping non-web-only changes and redundant post-merge `beta` pushes.
   - Downloads `web-dist` (zero redundant rebuilds), passes the same `vars.VITE_*` / `vars.CAPY_ANDROID_SHA256_CERT_FINGERPRINTS` env values baked into `web-dist`, restores cached `web/node_modules` and Playwright Chromium (`~/.cache/ms-playwright`), checks `ldd` to skip redundant `apt-get` `install-deps` when shared libraries are already satisfied, and executes `npm run test:e2e -- --workers=4` (zero duplicate Part 1 unit re-runs, 4 parallel isolated BrowserContext worker lanes).
4. **Deploy Preview (`deploy_preview`) & Production Deploy Pages (`deploy`) Jobs (`deploy-branch.yml`, `contents: write`, `pages: write`, `id-token: write`, `pull-requests: write`)**:
   - **Unblocked Previews (`deploy_preview`, `target_dir != '.'`)**: Depends on `needs: [prepare, build, android_build]` (never waiting on `Playwright E2E`), publishing open Alpha PR previews to `/alpha/<number>/` + `/alpha/<number>/capy.apk` (with PR comment links) and `beta` pushes to `/beta/` ([Capy Beta](https://shthed.github.io/capy/beta/)) + `/beta/capy.apk` in under 2 minutes while refreshing `/alpha/manifest.json` and root `404.html` (`--refresh-404` on `beta`).
   - **E2E-Gated Production (`deploy`, `target_dir == '.'`)**: Depends on `needs: [prepare, build, android_build, e2e_release_gate]`, strictly requiring `e2e_release_gate == 'success'` (or `skipped` only on non-web `has_web_changes == 'false'` pushes) before publishing `main` to `/` ([Capy Production](https://shthed.github.io/capy/), preserving `/alpha/` and `/beta/`) with refreshed `404.html` (`--refresh-404`) as a single squashed orphan commit on `gh-pages`.
   - Both jobs are guarded by `github.event.repository.has_pages == true` (excluding `dependabot[bot]` PRs, external forks, and `is_main_sync` fast-path PRs), serialized under the shared `deploy-pages` concurrency lock (`cancel-in-progress: false`), and upload the Pages artifact with `include-hidden-files: true` across [`deploy-branch.yml`](./.github/workflows/deploy-branch.yml), [`cleanup-closed-pr.yml`](./.github/workflows/cleanup-closed-pr.yml), and [`cleanup-branches.yml`](./.github/workflows/cleanup-branches.yml) (validated by pure-Node [`yamlParser.mjs`](./web/scripts/tests/unit/yamlParser.mjs) assertions invoked via [`web/scripts/test.mjs`](./web/scripts/test.mjs)) so dotfiles such as `.well-known/assetlinks.json` survive deploys and cleanup sweeps.
5. **Release & Play Store Bundle Workflow ([`release.yml`](./.github/workflows/release.yml))**:
   - Triggered on `v*.*.*` Git tags (or `workflow_dispatch`), requiring `CAPY_KEYSTORE_BASE64`, `CAPY_KEYSTORE_PASSWORD`, `CAPY_KEY_ALIAS`, and `CAPY_KEY_PASSWORD` before executing `app:testDebugUnitTest app:lintVitalRelease app:assembleRelease app:bundleRelease` to publish `capy-<tag>.apk` (plus unversioned `capy.apk` on stable releases), Google Play Store `capy-<tag>.aab`, and `capy-web-<tag>.tgz` with release notes extracted via [`.github/scripts/compile-changelog.mjs`](./.github/scripts/compile-changelog.mjs).
6. **Deploy Cloudflare Worker Job ([`deploy-cloudflare.yml`](./.github/workflows/deploy-cloudflare.yml), `contents: read`)**:
   - Runs `npm run test:sanity`, `npm run lint`, and `npm run build`, deploys `web/dist` Static Assets and `worker/index.ts` (`CoopRoomDurableObject`) to [capypaint.com](https://capypaint.com/) via `cloudflare/wrangler-action@v4` when `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` are set (skipping cleanly in `< 2s` when unconfigured), and verifies [capypaint.com/api/health](https://capypaint.com/api/health).
